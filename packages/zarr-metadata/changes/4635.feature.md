A TypedDict read by `zarr_metadata.typed_json.check`, or used as a definition's configuration, may now bound the length of an array with annotated-types' `MinLen`, `MaxLen` and `Len`, as pydantic reads them: `Annotated[tuple[int, ...], MinLen(1)]` is a non-empty array. An array outside its bounds is an `invalid_value` problem whose `ctx` holds `min_length` or `max_length`, and the JSON Schema writes `minItems` and `maxItems`. A length bound on anything but an array raises `TypeError`. An array document's `codecs`, the `sharding_indexed` codec's `codecs` and `index_codecs`, and each list in a `rectilinear` chunk grid's `chunk_shapes` now say on their types that they are never empty, so `check` also refuses `"codecs": []`. The `null_terminated_bytes` and zarr-python `raw_bytes` data types declare `length_bytes` at least 1, and `struct` declares at least one field, on their types, so their JSON Schemas now say so too.
