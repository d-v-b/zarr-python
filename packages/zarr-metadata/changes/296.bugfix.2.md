Codec configurations are now judged against the array each codec
*receives* — as transformed by every codec before it in the chain —
rather than against the document's top-level `shape` and chunk grid.

A codec pipeline is a sequence of transformations: `transpose` permutes
the shape, `cast_value` changes the data type, and a `sharding_indexed`
codec that follows either one sees the transformed array. Rules that read
the chunk grid directly were wrong whenever anything preceded them. The
sharding divisibility rule gave wrong verdicts in *both* directions with
a transpose in front of it: for a `(6, 4)` chunk transposed to `(4, 6)`,
an inner chunk of `(3, 2)` was accepted (3 does not divide 4) and `(2, 3)`
was rejected (it divides). Both are now correct.

New in `zarr_metadata.rules`: `ArraySpec` (the shape, data type, and
fill value a codec receives) and `propagate`, which walks a chain handing
each codec its incoming spec. A field this package cannot determine is
the `UNKNOWN` sentinel, never `None` — `fill_value: null` is a real,
spec-valid value for null-permitting data types, and must stay
distinguishable from "not ours to say". Every array->array codec registers a `spec_transition`
next to its rules — `transpose` permutes the shape, `cast_value` replaces
the data type — and entity rules receive the incoming spec as a third
argument. Two policies are deliberate: an unknown codec stops propagation
so downstream geometry declines rather than guesses (the same stance as
the exactly-one-array->bytes count), and shape propagation ends at the
array->bytes boundary while the data type carries through.

**A scope boundary, stated.** `cast_value` transforms the fill value by
numeric semantics — rounding modes, out-of-range clamp and wrap, scalar
maps — and the spec makes a failed fill-value round-trip a MUST error.
Deciding that means implementing the cast, which is a different category
of work from anything else in this package (structure and composition,
both decidable from JSON) and has no bounded partial version. So
`cast_value`'s transition propagates its target data type, a
compositional fact it declares in configuration, and sets the fill value
to `UNKNOWN`. Rules downstream that read the fill value decline, and the
round-trip requirement is recorded on the transition as belonging to
whatever implements the codec, rather than silently unenforced.

Sharding's inner pipeline is now a chain that starts from the inner
chunk with the incoming data type and fill value, replacing the
synthetic-document approximation; nested transposes and nested shards
inside a shard are judged against the inner chunk, recursively.
