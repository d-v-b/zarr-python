Add `zarr-storage`, a new package with a Zarr-agnostic key-value storage API: `Store` and `AsyncStore` views over memory, local-filesystem and obstore backends, with the same operations as sync methods and as coroutines, conditional reads and writes (`get_if_changed`, `put_if_absent`, `put_if_match`, `delete_if_match`), byte-range reads, reads into caller buffers, and batches (`get_many`, `get_into_many`, `put_many`, `delete_many`) that run concurrently where the backend can. It ships a conformance suite in `zarr_storage.testing` that any backend can run.
