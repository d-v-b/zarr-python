Tidied the validation added with the recent boundary audit so each rule has one owner. Index-array selectors are checked against the domain in the caller's dtype and narrowed to `intp` by that check, so a coordinate past the `intp` range is a `BoundsCheckError` naming the value and the domain rather than an `OverflowError`; wire `index_array` leaves are held to the message layer's one definition of a JSON integer (a Python `int` that is not a `bool`; NumPy integer scalars in a hand-built document are no longer accepted), and the rejection names the offending leaf; a grid that returns a negative chunk id is reported instead of grouped; `DimensionGridLike` again declares chunk ids as `[0, n)` with lookups outside the extent raising, and the planner's negative-chunk-id fallback is gone; the "index array varies over an axis a slice map also reads" rejection is one predicate, the new `IndexTransform.index_array_shares_affine_axis` property. The pointwise chunk-plan oracle draws fewer degenerate domains and reports its reach, and `just lint` pins the same ruff as the root pre-commit configuration.

A source with no advertised write grid (`write_chunk_sizes` or `chunks`) is now written as one grid cell: a non-affine write reads the selection's bounding box once, updates it in memory, and writes it back with one basic assignment, where it previously issued one scalar assignment per selected element. Every source written through a non-affine selection must therefore support basic slice reads, and a hand-built transform in which two output maps read one input axis now raises the planner's `ValueError` before any cell is written, as it already did for reads. `Partition.box` is a property derived from `projection.chunk_domain`. `EagerArrayAdapter` stays: Dask reads blocks from a bare `LazyArray`, but it infers its block prototype by indexing the input with empty slices, so reductions such as `mean` need the adapter (or `meta=`); its documentation now says so.
