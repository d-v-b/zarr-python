Chunk plans now have a factored, columnar form. `ChunkPlan.partition()`
returns a `GridPartition`: one `StridedSet` or
`IndexedSet` table per output dimension the transform reads independently,
plus `joint_sets`, one table per connected index-array component. A `ChunkProjection`
is one row of each table and is derived on demand, so planning costs the sum
of the touched chunks per axis rather than their product, and a vectorized
consumer can read the tables without materializing a projection per chunk.
The projections retain the same coordinate mapping. Correlated projections
keep residual slices symbolic and index-array broadcast axes compact.
A hand-built transform in which two output maps read one input axis (a
diagonal, which no selection produces) remains supported by iteration, while `partition()` raises `ValueError`
because its tables are per output dimension.
`chunk_coord_batches()` exposes bounded coordinate arrays for large plans.
The tables memoize their read-only chunk-local coordinate columns.

The pre-1.0 `joint` attribute is replaced by `joint_sets`. `row_shape` lists
all component-table lengths after the per-axis lengths. Correlated rows now
have one synthetic axis per nonconstant component, followed by residual axes;
iteration follows this factored order. Vectorized selection preserves singleton
broadcast axes, avoiding expansion of independent index arrays during compilation.
A direct projection iterator avoids component-product overhead when one
index-array component covers every input and output axis.

An internal selector-execution prototype adds direct paths for basic slices
and dense sorted coordinates, with an adapter for the current sharding codec.
It is opt-in and does not replace Zarr's existing indexers.
