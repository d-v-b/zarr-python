Add `Array.validate_write` and `AsyncArray.validate_write`, which report the chunk shapes in a selection that the array's codecs reject, without writing anything or doing any I/O. They take any selection `Array.__setitem__` takes and return one `zarr.types.ChunkProblem` per rejected chunk shape, naming the kind of problem, the shape, the first selected chunk with that shape, and the codec that rejected it. Only an array whose codecs were validated against a single representative chunk can have problems here; that requires a rectilinear chunk grid, which is experimental, and a codec that does not declare how it changes the grid.
