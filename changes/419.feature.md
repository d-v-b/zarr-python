Added `zarr.experimental.ArrayIO` and `zarr.experimental.AsyncArrayIO`, an explicit-IO layer over Zarr arrays. Constructing one performs no IO against storage: storing metadata (`store_metadata`), storing or reading chunks (`setitem` / `getitem`), and their erasing inverses (`erase_metadata`, `erase_chunk`, `erase_chunks`) are explicit method calls that run in whatever order the caller chooses, so chunks can be written before metadata. `open` auto-detects the Zarr format by default, as `zarrs` does.
`verify` reads the stored metadata and raises, naming each differing field, when it does not match the metadata the instance is bound to.
`AsyncArray` now wraps an `AsyncArrayIO` and delegates its metadata and selection IO to it; the two layers share one state, and `to_array()` returns an array over the same binding.
